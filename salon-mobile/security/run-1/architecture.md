# Architecture (salon-mobile, run-1, quick profile)

1. **Product and principals.** One-salon phone app (Expo 57 / React Native 0.86 / react-native-web 0.21), no server. All data (customers with phone numbers, visits, wallet balances and ledger, staff, attendance selfies, owner and staff password hashes, privacy log) lives on the device in AsyncStorage key `salon:data:v1`; session in `salon:session` (src/domain/store.ts). Principals: the **owner** (owner password; full authority), **stylists/staff** (mobile + password; counter, visits, bookings, own leave/attendance), the **customer at the counter** (reads back 4-digit WhatsApp codes for wallet spends above ₹500 and referrals), **anyone who picks up an unlocked phone** (sessions never expire), a **file supplied to the owner** (backup restore picks any file), and on the web build **whoever controls the browser storage / host page**. Protected resources: wallet money and referral credit, bill integrity (undo/void), owner-only settings and staff management, the owner password, customer PII.
2. **Comparable baseline.** Indian salon SaaS (Zylu, DINGG, Salonist; COMPETITOR-FIXES.md) are server-backed with per-user accounts; this app instead trusts one device and UI role gating. Calibration only.
3. **Stack and deployment.** Managed Expo; `android/` and `ios/` are not in the repo (no manifest, allowBackup, signing visible). Web export + `scripts/web-single-file.py` produce a single HTML published as a claude.ai artifact; that shim mirrors every `salon:*` localStorage key to the host's `db` capability and restores it before boot. Offline checks: vitest (83 tests pass in the parent sandbox), tsc. No emulator or Android toolchain.
4. **Entry surfaces → sinks.** Login/Setup screens → `checkSecret` / `setOwnerSecret` → session JSON. Staff screens (Counter, Visit, Profile, Calendar, Me) → engine ops (`createCustomer`, `startVisit`, `addVisitExtra`, `checkoutVisit`, `voidVisit`, `topUp`, `closeWallet`, `approveVisitExtras`) → wallet/visit records. WhatsApp code screen (Guards.tsx, `Math.random`, no attempt limit) → boolean `walletCodeOk`/`referralVerified` trusted by engine. Backup file (share.ts `pickTextFile` */*) → `readBackup` (checks.ts) → `migrate` → `restoreBackup` replaces all data incl. `owner.secret`, catalog prices, check limits, `photoKey`s → later `deletePhotos` path join and `tel:`/`wa.me` links. Export: full data incl. hashes to share sheet; xlsx export (zip only). Outbound `Linking.openURL` for `wa.me` (message encoded, phone not) and `tel:`; `Me.tsx` opens configured legal URLs without scheme check. Stored-state load: `salon:data:v1` and `salon:session` parsed without validation; parse failure falls back to demo data with known owner password `owner1234`.
5. **Trust boundaries and strongest control.**
   - Owner vs staff: enforced only in UI components (hidden buttons, `getSession()?.role` in TopUpSheet, `isOwner`/OwnerApproval password in Visit); engine functions take no role; router renders any route for any session; `voidVisit` takes caller-supplied `by`.
   - Authentication: SHA-256(salt+password), single iteration, min length 4, `===` compare, no lockout; demo credentials shown on login while `data.demo`.
   - Customer verification: 4-digit code, compared in the component.
   - Backup integrity: JSON shape checks only, no signature; gated by being in owner area, no password re-prompt.
   - Device: AsyncStorage plaintext; selfies under documentDirectory/attendance (native) or localStorage data URIs (web).
6. **Starting paths.** src/domain/{engine,store,auth,checks,rules,seed,types,xlsx}.ts, src/components/{Guards,TopUpSheet,BookSheet}.tsx, src/screens/{Login,Visit,Counter,Profile,Me,Calendar,Reminders,LeaveRequests,Attendance}.tsx, src/screens/owner/*.tsx, src/platform/{photos,share,hasher}.ts, App.tsx, src/nav/*, scripts/web-single-file.py, scripts/build-legal.mjs, app.json.
7. **Prior coverage.** No prior ledger or findings exist; this is the first run.
8. **Companion selection.** CLIENT-SIDE.md (web build stores session and data in browser storage and is restored by a host shim; outbound navigation). DESKTOP-MOBILE-AND-LOCAL-IPC.md (mobile app: file-open of a backup, credential store, shared-device account switch/logout). DATA-ISOLATION-AND-LIFECYCLE.md (backup export/restore, deletion/retention purge of photos and customers). Excluded: WEB-PROTOCOL-AND-AUTH (no HTTP server, cookies, OAuth), PROTOCOLS-RPC (no RPC/broker), CLOUD (no IaC in repo), SUPPLY-CHAIN (no CI/release pipeline in repo; dependency check left to Obvious things), MEMORY-SAFETY (no native code in repo), AI-AND-LLM (no model in the app), RESOURCE-EXHAUSTION (single-user device, no shared service).
